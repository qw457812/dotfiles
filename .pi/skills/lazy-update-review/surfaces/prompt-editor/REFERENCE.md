# Prompt-editor compatibility contracts

Compare current local source and tests with the frozen target. These checks encode local policy and failure modes, not a copy of either editor's implementation. When testing the actual subclass, `tests/prompt-editor/runtime.test.ts` loads the real pinned pi-vim; fixture-only and type checks are not target runtime evidence.

## Wrapper and replacement lifecycle

- **Wrapper:** `ensurePiVimWrapper()` must re-export the entry and every private helper from the same pi-vim under `getAgentDir()/npm/node_modules`. Check generated exports against the generator before attributing missing exports to upstream.
- **Factory parity:** compare the replacement constructor, every setter/callback and setup/cleanup step with pi-vim's target `session_start` and `session_shutdown`. Reuse upstream settings resolvers to retain trust/precedence (including global-only clipboard-copy policy). Resolve command names at submit time and compare the local builtin list to `EX_BUILTIN_COMMAND_NAMES`; `pi.getCommands()` omits builtins. Explicitly justify local ownership, e.g. cursor shape or thinking border.
- **Host transfer:** compare `setCustomEditorComponent()` with the host fixture in `lifecycle.test.ts`. Pi owns text/callback transfer and can overwrite the border after the factory returns. Check late competing factory installs, coalescing, retained drafts and both asynchronously loaded and new history. Reinstalls copy the current session's history (including an empty array), reset browsing, and hydrate the branch snapshot only for the first install. New sessions isolate histories. Shutdown invalidates queued callbacks, restores the bound setter, unsubscribes focus and releases cursor/mode-change resources.

## Render and degradation

- **Full upstream render:** account for constructor options, editor preflight, selection paint and display width bookkeeping. Render at the actual prefix-reduced width, except when the prefix cannot fit. Failed preflight delegates input and render before local decorations, remaps or cursor ownership. Test missing actions at the real entry point, narrow-to-wide resize and wrapped `gj`/`gk`. If upstream caches render output, copy before mutation.
- **Surface colors:** both Visual modes share the `visual` key; Ex is a Normal-mode substate. Supply the complete label colorizer map for both widths. Use upstream `borderSync`/`labelSync` resolvers with explicit host fallback; retain colored non-Insert prefixes unless the border always carries the mode. Selection paint uses live theme colors and falls back to reverse video for missing/reset-only colors.
- **Placement:** upstream owns labels and pending feedback. Preserve the accepted trailing dashes after a bottom-right label and its placement on the last rendered row (even during autocomplete). Top-left stays on the top border. Test both, and keep cursor transformations out of borders, labels and suggestion rows.

## Cursor ownership

- **One writer:** local `cursor.ts` owns DECSCUSR and visibility; disable pi-vim's competing cursor runtime while using its shape resolver. Blur forces visibility off without changing the preference. Read the live preference only while focused and apply effective visibility outside render. On failed preflight release ownership and restore the configured preference directly on the injected TUI (explicit setting beats `PI_HARDWARE_CURSOR`, and a competing factory can force visibility on).
- **Renderer and native focus:** retain the stable Proxy setter across reinstalls and exercise a live regular/fullscreen switch. Test actual `ESC[I`/`ESC[O` input separately from injected `my:focus_change`; a fullscreen viewport handler can consume native focus events before the extension. Verify shutdown resets shape even if no editor was installed.
- **Raw output:** compare Pi's exact `Editor` marker production and final TUI fake-cursor resolution (not just pi-vim's cursor helper). Use `cursor.test.ts` plus interactive output to check both cursor modes, missing hardware markers, clipped APC endings, width/graphemes, selection styles and body-only unwrapping. If the protocol changes, update the helper's source revision comment.

## Navigation and shortcuts

- **Pending input owns the next key:** verify Ex and bracketed paste, operators, pending arguments (`g`, counted `g`, `Z`, find/replace and text objects), modal Escape, undo/redo and submit. Invalid `ZlQ`/`ZjQ` suffixes must not retain a quit prefix. Guarded `cl` delegates to `s`; successful `cc` must clear both the visible picker and in-flight autocomplete.
- **Motion:** verify the private layouts, grapheme segmentation, cursor/sticky and display-column setters and pending state (including `refreshPendingDispatchRestore`) in `NavigationEditorRuntime`. Local `h`/`l` clamp to grapheme starts (at the end sentinel, `l` is a no-op and `h` returns to the last grapheme); `H`/`L` use display endpoints and delegate pending counts. Clear stale wanted columns and refresh autocomplete/pending restoration as required. Bare `j`/`k` use upstream display-row motions, not history. Literal Normal `gj` alone aliases `J`: preserve the prefix count, undo/dot replay and EOF no-op behavior. Synthetic `gj`, Visual/operator motions, counted `g` and `gJ` stay upstream.
- **Shortcut precedence:** compare `claimNavigationShortcut` and every `NavigationShortcutRuntime` member to upstream dispatch and `createCursorBindingResolver`. Offer the original chord exactly once to the extension callback for locally consumed Normal-mode controls/arrows/Backspace only, respecting modal and submit exclusions. A claim clears wanted column and pending/repeat state; restore async Ex state even on a throw. App actions stay upstream. Delegate Ctrl+d/u/f/b scrolling in Normal/Visual/V-Line; test counts, actual render width, resize and Ctrl+d staying in an empty prompt.
- **Evidence:** run `navigation.test.ts` and `runtime.test.ts` against the target. Exercise wraps, multiline boundaries, emoji/combining graphemes, `v$` then Escape/`l`, `H`/`L` in each selection mode, claimed/unclaimed shortcuts, `rj`/`rk`/`rH`/`rL`, split paste and async Ex restoration. For changed shortcuts/scrolling check the actual `PromptEditor` in regular and fullscreen modes.

## Visual paste

Compare `VisualPasteEditorRuntime` with upstream Visual dispatch, safe put normalization, ranges, register/mirror policy and undo windows. Resolve the effective payload before deleting so a control-only payload is a no-op. Keep the original raw register when only the payload is normalized. `p` keeps the deleted selection in the unnamed register; `P` preserves the original register without mirroring deletion. Preserve counts and the absolute characterwise start at end-of-line; a final linewise selection below line zero puts after. Pending operator/motion/replace/text-object arguments stay with pi-vim.

Run `visual-paste.test.ts` and target `runtime.test.ts`: verify buffer, registers and one-step undo for both Visual modes, both puts, counts, buffer-end selections and pending inputs such as `fp`/`tp` and `g`. Missing private members must surface as failures, not silent passes.

## Clipboard transport

Runtime transport is upstream-owned. Compare pi-vim's clipboard mirror/platform helpers and Pi's `copyToClipboard` when changed; verify settings still flow through `setClipboardMirrorPolicy`. Check UTF-8, successful empty read vs `null`, register fallback, timeout budget, mirror ordering/cancellation and native backend detection. Snapshot the clipboard before native writes, restore in `finally`, and skip writes if snapshot fails. Report platforms not tested.
